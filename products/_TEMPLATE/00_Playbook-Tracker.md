**Status** is one of `NOT STARTED` · `DRAFT` · `PROPOSED` · `LOCKED` · `STALE`, matching the
artifact's own status line. `REVIEW-DUE` is added (e.g. `LOCKED · REVIEW-DUE`) when a metric
threshold set in `14_Metrics-and-Feedback.md` fires, or a scheduled review date passes. It means
re-check the pillar, not that it is wrong. Only the owner marks `LOCKED`. **Done when** counts the ticked boxes
below. A pillar is done only when every box is ticked, and every tick points to the evidence for it.
**Owner** is the person accountable for the pillar in this project, not the skill.

## Done-when checklists

Tick a box only when the artifact shows it. Add the section or file after the tick, e.g.
`- [x] TAM, SAM and SOM are calculated … → 01_Segmentation.md §2`. A box that does not apply
to this project gets `N/A — <reason>`, not a tick.

### Step 0 — Discovery and the Business Profile

- [ ] The facts are recorded with their sources: product, public claims vs truth, legal promises, prices and costs, the evidence count
- [ ] The Business Profile is filled, all nine fields (engagement only for client work), each tagged with its evidence
- [ ] Every unknown field is a question for the owner, and P1–P5 are answered
- [ ] The owner (or client) has confirmed the profile

### Pillar 1 — Market Segmentation & Targeting

- [ ] TAM, SAM and SOM are calculated, with the method written down
- [ ] Segments are described with at least three lenses, not industry alone
- [ ] Each candidate segment is checked as measurable, accessible, profitable and actionable
- [ ] A few target segments are chosen and ranked, and the rest are parked
- [ ] The choice is validated with data (CRM, LinkedIn, market research)
- [ ] The next review date is set, 6–12 months out

### Pillar 2 — ICP & Buying Center

- [ ] The 10–20 best customers are pulled and 5–10 champions interviewed
- [ ] Candidate ICPs pass the operational-fit filter and are scored on the six dimensions
- [ ] The ICP statement is written from the template
- [ ] The anti-ICP is written
- [ ] The buying center is mapped: all six roles, who signs and who can block
- [ ] The ICP is validated: account count in Sales Navigator or Apollo, and one micro-campaign

### Pillar 3 — Value Proposition & Positioning

- [ ] The Value Proposition Canvas is filled for each ICP, using words from 5 customer interviews
- [ ] 3–5 value drivers are chosen, each with a KPI, a baseline and a target
- [ ] Every claim is paired with 1–2 proof points and a risk reverser
- [ ] The category and frame of reference are chosen
- [ ] The positioning statement is written, and its only-ness claim passes the "competitor tomorrow" test
- [ ] Each alternative is scripted: do nothing, build in-house, a generic provider, a tool alone
- [ ] The 30–60 day validation targets are set

### Pillar 4 — Messaging & Channels

- [ ] The one-liner and three message pillars are written, each with proof and its main objection
- [ ] The messaging matrix is filled: persona × stage
- [ ] A CTA is chosen for each stage
- [ ] A few channels are chosen, each with one primary metric
- [ ] Copy kits are drafted for the chosen channels

### Pillar 5 — Proof System

- [ ] The claims → evidence grid is filled: 2–3 provable claims per message pillar, each with an owner
- [ ] Every number is date-stamped and could be checked by a skeptical CFO
- [ ] Consent is recorded for each client at one of the three levels
- [ ] Proof fields are in the onboarding and offboarding forms, and the CRM dashboard is saved
- [ ] One proof format is ready per persona and stage
- [ ] Risk reversal is chosen, with success defined and conditions set
- [ ] A "proof used?" checkbox is on every CRM stage change

### Pillar 6 — Packaging & Pricing

- [ ] The value ladder is drawn: each rung has an offer, a price, a job and a bridge to the next rung
- [ ] Each offer is written with the 8 packaging blocks
- [ ] The floor is calculated from real delivery cost and overhead
- [ ] The ceiling is calculated from client value and a capture rate
- [ ] Competitors are benchmarked
- [ ] There are no more than three tiers, named by maturity
- [ ] Routing rules are written for moving up, down-selling and following up a "no"
- [ ] A price test is planned on 5–10 deals

### Pillar 7 — Demand Generation

- [ ] Each funnel stage has an objective, audience, activity, conversion action, KPI and follow-up
- [ ] One funnel map is chosen, with the reason written down
- [ ] Two channels are chosen: one to capture, one to build trust
- [ ] The lead magnet, landing page, thank-you page and nurture sequence are built
- [ ] Lead scoring bands are set
- [ ] The launch QA checklist is passed
- [ ] The 30-day sprint is set: 1 funnel, 2 channels, up to 3 experiments with stop rules

### Pillar 8 — GTM Motion

- [ ] The motion is chosen with the decision rules, and the reason is written down (deal size, how buyers decide)
- [ ] Routes to market are listed, each with a role and a first step
- [ ] Each role is assigned to a named person

### Pillar 9 — Outbound

- [ ] The legal gate is cleared
- [ ] The list is built at segment and persona level, and accounts are tiered 1/2/3
- [ ] Every lead is qualified before sending
- [ ] The sequence is written: one problem per message, a real approved proof point, a one-word-reply CTA
- [ ] Domains are warmed and daily sending limits are set
- [ ] A person edits every message before it goes out
- [ ] The weekly outbound dashboard is live

### Pillar 10 — Revenue Process & SLAs

- [ ] Sales stages are defined, each with exit criteria
- [ ] CRM pipeline stages and exit rules are live, with a separate delivery pipeline
- [ ] One qualification framework is chosen
- [ ] SLAs are agreed between marketing, sales and delivery
- [ ] Automation triggers are live
- [ ] The qualification-call and discovery scripts are ready
- [ ] The marketing–sales contract is signed, with all five definitions
- [ ] Onboarding steps and the reporting cadence are set

### Pillar 11 — Enablement

- [ ] The enablement checklist above is fully ticked
- [ ] Every toolkit asset exists and is linked to its sales stage
- [ ] The tech stack is set up, with consent and data processing agreements covered
- [ ] The ROI model is built with three scenarios
- [ ] The proposal template is ready with all 12 sections

### Pillar 12 — Metrics & Feedback

- [ ] The KPI dashboard is live, with leading and lagging indicators per stage
- [ ] CAC is tracked two ways: ads only and fully loaded
- [ ] The weekly scorecard is filled and the weekly growth meeting is on the calendar
- [ ] The test backlog is ranked by ICE
- [ ] Each review in the cadence table is on the calendar with an owner
